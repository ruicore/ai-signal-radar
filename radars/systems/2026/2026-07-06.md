## 1️⃣ 本周最重要的 5 条

### ① Microsoft Research：SkillOpt 把 agent skills 从“手写提示词”变成可训练参数

**Source**：Microsoft Research — *SkillOpt: Agent skills as trainable parameters*；**Time**：2026-06-30

Microsoft Research 发布 SkillOpt，把 agent 的 skill file 当成可训练参数。Agent 执行任务、收集轨迹，再由 optimizer 对 skill 文件做受限的 add / delete / replace 编辑，并通过验证集决定是否接受。报告称其在 52 个评估单元中全部达到最佳或并列最佳，并在 Codex 与 Claude Code harness 中提升。

核心 loop：

```text
task execution → trajectory collection → bounded skill edits
→ validation gate → accept / reject → rejected edits as negative feedback
```

它引入 textual learning rate、edit budget、held-out validation、slow/meta updates，把 skill 更新限制在可审计、可回滚的小范围内。工程启发是把 skill 变成 versioned + evaluated + optimizable artifact，而不是只凭感觉维护提示词。

### ② GitHub：Copilot control plane 正在补齐 budget、telemetry、identity、policy

**Source**：GitHub Changelog — Copilot session limits / agent session data / Actions `GITHUB_TOKEN` / cost centers / managed settings；**Time**：2026-07-01 → 2026-07-02

GitHub 连续发布 Copilot agent 控制面能力：CLI / SDK 支持 session AI credit limits；企业可访问 agent session data，包括 prompts、responses、tool calls；GitHub Actions 使用内置 `GITHUB_TOKEN`；cost centers 支持 AI credit pools；managed settings 支持组织统一下发 CLI / VS Code 策略。

这些平台原语把 coding agent 推向企业可审计、可控、可计费的生产 workload：session budget、session telemetry、短期 CI identity、cost attribution 和 policy distribution。agent run 至少应记录 `run_id`、`actor_id`、`repo`、`budget_usd`、`spent_usd`、tools、model/tool calls 和 final status。

### ③ AWS：AgentCore healthcare claims pipeline 强调 deterministic supervisor

**Source**：AWS Machine Learning Blog — *Build an agentic AI healthcare claims pipeline with Amazon Bedrock AgentCore and Amazon Bedrock Data Automation*；**Time**：2026-06-29

AWS 展示 healthcare claims pipeline：S3 上传后由 Lambda 触发，Bedrock Data Automation 抽取文档，Strands agent 结合 HealthLake 验证 patient / provider，生成 FHIR Claim，再由 SNS 输出摘要。

```text
S3 upload → Lambda trigger → document extraction → agent validation
→ HealthLake lookup → FHIR Claim transformation → deterministic supervisor → SNS
```

关键判断是很多流程逻辑应在 design time 显式编码，而不是交给 agent 推断顺序；deterministic supervisor 负责仲裁、异常处理和成本控制。生产系统应区分 `workflow owner = deterministic orchestrator`、`reasoning owner = agent`、`approval owner = policy / human / supervisor`。

### ④ Anthropic：Claude Science 展示“可审计 agent workbench”形态

**Source**：Anthropic — *Claude Science*；**Time**：2026-06-30

Claude Science 集成 tools、packages、计算资源、curated skills / connectors，并强调每个输出都有 auditable artifact：代码、环境、消息历史和计算过程可追溯。形态包括 coordinating agent、specialist agents、reviewer agent、local / SSH / HPC / Modal GPU compute、auditable artifacts 和 forkable sessions。

高价值 agent 系统正在从聊天界面升级为 `workbench + artifact ledger + compute boundary + specialist agents + reviewer + reproducibility`。复杂 agent 输出应保存 source input、code / command、environment、tool calls、reviewer result 和 human correction，而不只是最终答案。

### ⑤ Microsoft Research：Memora 把 long-term memory 改成摘要索引 + 按需检索

**Source**：Microsoft Research — *Memora: A memory system for long-horizon language agents*；**Time**：2026-06-29

Memora 将 rich memory storage 与 lightweight retrieval abstraction 解耦，通过 primary abstractions / cue anchors 帮助 agent 检索需要的历史，并用 policy-guided retriever 和 iterative refinement 注入紧凑上下文。

```text
rich memory store → primary abstractions → cue anchors
→ policy-guided retriever → iterative refinement → compact context
```

长期记忆不应等同于追加全部消息或简单 vector search，而应包含 storage、abstraction、retrieval policy 和 provenance。可执行的三层拆分是 raw events、memory abstractions、retrieval policy。

## 5️⃣ 一个工程行动（1–3 小时）：Skill Optimization Harness

建立 `agent_skills/`、`agent_skill_versions/`、`evals/`、`logs/` 四层结构。先不做自动 optimizer，用人工或 LLM 生成候选 skill edit，但必须有 validation gate 和 rejected-edit log。候选版本只有在 frozen eval 上超过 baseline 且没有破坏其他 case、过长或缺少 change summary 时才接受。

最小 schema 包含 `skill_name`、`version`、`path`、`parent_version`、`change_summary`、`eval_score`、`accepted`、`rejected_reason`、`created_at`。建议用 5–10 个真实任务做 before / after：repo review、test generation、refactor planning、migration checklist、failure analysis。
